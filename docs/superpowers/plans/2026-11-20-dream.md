# /dream Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user-invoked `/dream` skill that reads recent sessions across all projects, finds recurring
patterns, and, after the user approves the exact change, writes skills or rules into the user's own layer.

**Architecture:** Two small bash scripts do the deterministic parts: `collect.sh` picks which transcripts to
read, and `target-ok.sh` refuses any write target inside the dotfiles clone. `SKILL.md` drives the judgment
part (find patterns, show, approve, write, prove) and reuses `/learn`'s `digest.sh` and failure-mode table.

**Tech Stack:** bash, jq, `find` (as `digest.sh` uses), `bin/skill-eval` for the skill eval.

**Spec:** `docs/superpowers/specs/2026-11-20-dream-design.md`

## Global Constraints

- Manual only: `disable-model-invocation: true`; no schedule, no background run.
- A pattern needs at least 2 occurrences, with evidence quoted for each.
- Nothing is written before the user OKs the exact file/diff and its absolute path.
- Writes go only to: `$WORK_CONTEXT/rules.d/learned.rules`, `$WORK_CONTEXT/rules.d/check-commands.txt`
  (`WORK_CONTEXT` defaults to `~/work-context`), `~/.claude/skills/<name>/` (a real directory), `~/.claude/rules/<topic>.md`.
- Never write inside the dotfiles clone, even through a symlink. Hook-script or `settings.json` fixes are suggestions only.
- No commits of learned artifacts. Default window 7 days. Skip subagent transcripts and projects named `-private-tmp-*` / `-private-var-*`.
- Shell scripts pass shellcheck (run by format-on-edit and `bin/dotfiles-check`).

## Review Focus

1. A new skill directory doesn't exist yet: `target-ok.sh` must resolve the nearest existing parent, not fail. (Task 2 test)
2. `~/.claude/skills/<name>` is a symlink into the clone (a shipped skill): must be refused, not edited. (Task 2 test)
3. No transcripts in the window: `collect.sh` prints nothing and exits 0; the skill says there is nothing to learn. (Task 1 test)
4. `$WORK_CONTEXT` set to a custom folder: that folder is allowed, `~/work-context` is not assumed. (Task 2 test)
5. Many sessions: a cap (`--max`, default 40, newest first) keeps the digest volume bounded. (Task 1 test)

### Task 2: `target-ok.sh` guards every write

**Files:**
- Create: `claude/skills/dream/scripts/target-ok.sh` (executable)
- Modify: `claude/skills/dream/tests/run.sh` (add cases)

**Interfaces:**
- Produces: `target-ok.sh PATH` → exit 0 and prints the resolved path if allowed; exit 1 with the reason on stderr otherwise.
  Resolution: walk up to the nearest existing ancestor, `realpath` it (follows symlinks), re-append the missing tail.
  Clone root = `realpath "$(dirname "$(readlink -f "$0")")/../../../.."` (the repo the script ships in).
  Allowed iff the resolved path is NOT under the clone root AND is under one of:
  `$WORK_CONTEXT/rules.d/` (default `$HOME/work-context`), `$HOME/.claude/skills/<name>/`, `$HOME/.claude/rules/`.
  `HOME` and `WORK_CONTEXT` are read from the environment so tests can point them at a temp dir.

- [ ] **Step 1: Write the failing tests** with `HOME=$tmp/home WORK_CONTEXT=$tmp/wc`:
  - `$tmp/wc/rules.d/learned.rules` (doesn't exist yet) → 0
  - `$HOME/.claude/rules/prs.md` (folder doesn't exist yet) → 0
  - `$HOME/.claude/skills/new-skill/SKILL.md` (doesn't exist) → 0
  - `$HOME/.claude/skills/shipped` is a symlink to `<clone>/claude/skills/commit`; `$HOME/.claude/skills/shipped/SKILL.md` → 1, stderr mentions the clone
  - `$HOME/.claude/CLAUDE.md` → 1 (not an allowed destination)
  - `$HOME/work-context/rules.d/x.rules` while `WORK_CONTEXT=$tmp/wc` → 1
  - a path inside the clone, e.g. `<clone>/claude/hooks/ban-patterns.rules` → 1
